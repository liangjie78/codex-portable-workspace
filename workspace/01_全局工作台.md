# Codex 全局工作台与项目工作流

本文件定义 `{{WORKSPACE_ROOT}}` 作为 Codex 正式工作区时的目录、项目创建、修改和收尾规则。

## 工作区结构

```text
{{WORKSPACE_ROOT}}/
├── AGENTS.md
├── 00_本机环境与工具清单.md
├── 01_全局工作台.md
├── 02_Codex用户使用说明.md
└── Projects/
    └── Project-三位编号-项目名称/
```

工作区根目录不放项目源码、临时脚本、交付物或个人私有配置。

## 何时创建项目

满足以下任一条件时，创建独立项目目录：

- 需要长期保存多个文件、源码、素材、文档、输出或日志。
- 需要多轮规划、实现、验证、交付或复盘。
- 需要独立运行环境、服务、页面、脚本或文档集。
- 用户明确要求新建网站、工具、应用、系统或可复用资产。

简单问答、一次性命令、临时排查和单文件小改通常直接在当前任务完成。

## 项目目录

新项目格式：

```text
{{WORKSPACE_ROOT}}/Projects/Project-三位编号-项目名称/
```

标准结构：

```text
Project-001-项目名称/
├── README.md
├── AGENTS.md
├── 00_Project_Brief.md
├── 01_Requirements/
├── 02_Research/
├── 03_Source/
├── 04_Assets/
├── 05_Outputs/
├── 06_Logs/
└── 99_Retrospective.md
```

编号只递增、不复用；项目名简短、可识别，避免含糊名称和 Windows 非法字符。

## 开始修改前

1. 阅读本文件和工作区根目录 `AGENTS.md`。
2. 阅读目标项目的 `README.md`、`AGENTS.md`、`00_Project_Brief.md` 和 `99_Retrospective.md`（存在时）。
3. 阅读项目的包管理文件、CI 配置和相关实现，确认真实命令。
4. 明确目标、范围、验收标准和验证命令。
5. 只修改完成任务所需的文件；保留无关改动和未跟踪文件。

## 运行环境

- Codex 智能体默认使用 WSL2 Ubuntu + Bash。
- Windows 专属任务才使用 PowerShell 7；不要把 PowerShell 当作普通开发任务的默认 Shell。
- WSL 中使用 `/mnt/c/...`、`/mnt/d/...` 访问 Windows 文件；含空格的路径始终正确引用。
- 不把 `docker-desktop` 作为开发发行版。

## 文档职责

| 文件 | 唯一职责 |
| --- | --- |
| `README.md` | 项目介绍、使用方式和文档入口 |
| `AGENTS.md` | 项目特有命令、约定、边界和验证 |
| `00_Project_Brief.md` | 目标、范围、约束、交付物和验收标准 |
| `99_Retrospective.md` | 实际结果、偏差、问题和后续建议 |

避免在多个文件复制同一段规则；需要引用时链接原文。

## 收尾要求

- 运行与改动相匹配的测试、构建或静态检查。
- 最终交付物放入项目的 `05_Outputs/`。
- 关键验证结果和未解决事项写入 `06_Logs/`。
- 更新 `99_Retrospective.md`，记录实际结果和后续建议。
- 交付时说明改动、实际验证、未验证项和仍需用户决定的事项。
